## Accepted behavior and constraints

Use the complete answer-or-search response, not a separate sufficiency-only call. Initial search remains. Extra search is an explicit per-turn option initially off, with at most one additional selected-indexed-document lookup and at most two chat-model generations using the same selected installed model. Insufficient support yields a supported partial answer or an explanation of missing evidence. Show stage status and final supplied sources. Ordinary chat, saved conversations, proficiency, opt-in whole-CV text, protected policy/question and Stop remain supported. No new model/framework/install, native-tool requirement, side chat, autonomous workflow or compaction.

The model's sufficiency judgment remains fallible. First structured answer must be buffered and validated through provider completion before presentation/save; a search request grants no source authority. Server captures selected-file scope, never interprets an empty filter as all topic files. New evidence must survive context allocation to count as used. CV-off must not read CV artifacts; CV-on source eligibility is rechecked before subsequent model requests. Material effective-context/source/policy changes visibly stop rather than remix a turn.

## Prompt/snapshot branch before implementation

After pushing2753831, coder2 owns prompt/snapshot helpers and regressions. Proposed plan extends existing ChatPromptPlan with immutable retained SourceReference entries; feature-only instructions and labels enter before the existing context-budget pass, never after it. We reuse the existing planner rather than creating a second trimming implementation. Labels are assigned to full candidate sources before allocation and filtered by actually retained citations afterward, so labels need not be contiguous. Optional citation source_label lets the UI resolve them while older citations remain valid. Balancing initial/additional evidence will be explicit rather than trusting append order, because existing trimming prioritizes input order.

Code inspection also established that whole-question protection currently depends on profile/CV presence. We choose an unconditional shared protection correction, rather than a new feature-only flag that would preserve silent question shortening in ordinary chat. An oversized protected minimum must refuse before turn save. Regression tests precede that behavior change; any old expectation of shortened questions must be identified explicitly.

Snapshot alternatives were raw global revision checks or effective prompt-relevant projections. We retain the approved projection approach: unrelated proficiency revision changes are not material, but policy, goal, relevant familiarity/focus/preferences and selected source identity are. The implementation must have an actual production store adapter, not only synthetic reader callbacks. CV-off cannot inspect the registry/artifacts even for freshness; CV-on must additionally pin active source ID and eligibility, since identical extracted text alone cannot establish that the same allowed CV remains selected. This adds bounded revalidation I/O and detects changes at checks; it does not promise atomic transactions across stores. Production race tests and retained-source behavior remain this slice's validation work.
