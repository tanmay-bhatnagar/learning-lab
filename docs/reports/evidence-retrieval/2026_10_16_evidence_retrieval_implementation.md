## Accepted behavior and constraints

Use the complete answer-or-search response, not a separate sufficiency-only call. Initial search remains. Extra search is an explicit per-turn option initially off, with at most one additional selected-indexed-document lookup and at most two chat-model generations using the same selected installed model. Insufficient support yields a supported partial answer or an explanation of missing evidence. Show stage status and final supplied sources. Ordinary chat, saved conversations, proficiency, opt-in whole-CV text, protected policy/question and Stop remain supported. No new model/framework/install, native-tool requirement, side chat, autonomous workflow or compaction.

The model's sufficiency judgment remains fallible. First structured answer must be buffered and validated through provider completion before presentation/save; a search request grants no source authority. Server captures selected-file scope, never interprets an empty filter as all topic files. New evidence must survive context allocation to count as used. CV-off must not read CV artifacts; CV-on source eligibility is rechecked before subsequent model requests. Material effective-context/source/policy changes visibly stop rather than remix a turn.

## Source-freshness research clarification

Researcher independently traced original hashes and derived artifact reads. FileRecord.content_sha256 hashes original upload bytes (`parse_pipeline.py`), while MarkItDown/AnyDoc have no extracted-text hash; parser/version are provenance, not unique derived-artifact identity. Comparing those fields alone cannot establish identity of supplied passages. `TopicIndex.get_chunks(chunk_ids=..., file_ids=...)` supports a bounded scoped full-row re-read; map by ID because DB order differs from ranking. Recompute text SHA256, compare captured file/name/pages and effective supplied location/asset metadata, and reject missing/changed records. Skip empty reference sets rather than querying unfiltered. Unindexed selected Markdown needs its exact read bytes/artifactname pinned and rechecked through existing protected read_bytes. Valid legacy full-hash rows can participate without requiring newer original-hash/parser fields; invalid hash rows must fail the opt-in path without changing ordinary chat compatibility.

We choose exact supplied-source projection checks over whole-SQLite/all-corpus hashing, which would add work and reject unrelated embedding/index activity. Persistent artifact-generation IDs would be a larger later storage change. This checks supplied evidence at revalidation points and uses immutable in-memory copies for inference; it does not freeze unseen search-corpus rows, prevent external writes immediately after checks, or provide a transaction across stores. A requirement to search an identical complete corpus version would change this decision and need a generation/snapshot mechanism. Researcher ran source inspection only; synthetic real-index mutation/deletion/metadata/legacy/order tests and selected-Markdown mutation tests remain coder/integration validation. Findings are consolidated here rather than saved as another separate report. The unchanged frontend baseline passes211tests with pre-existing act warnings.
