# My proficiency — implementation study path

The feature has three distinct data sources: a complete extracted CV describes background; a generated assessment proposes preparatory concepts for one selected section; proficiency JSON records the learner's explicit answers. They work together without treating CV mentions or model guesses as self-reported comfort. The original discussion and alternatives remain in [the dated reports](reports/personalized-prerequisites/2026_10_12_personalized_prerequisites_plan.md); [implementation checkpoints](reports/personalized-prerequisites/2026_10_13_personalized_prerequisites_implementation.md) distinguish passing tests from unverified runtime behavior.

Read these modules in order:

1. [learner_profile.py](../services/api/lab/learner_profile.py): pure validation and immutable version1 transformations. IDs and timestamps are inputs. Registering suggestions creates pending rows and never answers the question for the learner. Batch save validates everything before one revision change.
2. [profile_store.py](../services/api/lab/profile_store.py) and [profile_parse.py](../services/api/lab/profile_parse.py): filesystem/parser boundaries. Original filename preservation and collision checks live here; canonical extraction is separate from chunks. A process lock rechecks revision/CV identity before publishing.
3. [prerequisites.py](../services/api/lab/prerequisites.py): complete section plus complete CV plus policy plus optional goal becomes a fresh request. No chat history is inherited. Context fit refuses whole-source overflow; the model schema and response validator constrain shape/refs/quotes, not teaching quality.
4. [prerequisite_store.py](../services/api/lab/prerequisite_store.py), [workflows/prerequisites.py](../services/api/lab/workflows/prerequisites.py) and [workflows/prerequisite_publication.py](../services/api/lab/workflows/prerequisite_publication.py): attempt lifecycle and LangGraph admission/execution; [web/prerequisites.py](../services/api/lab/web/prerequisites.py) is the HTTP adapter (see the [workflow study path](workflows.md)). Generating is not completed. Only validated provider completion and durable publication create actionable cards; cancellation/error preserves history. Profile and topic writes are independently atomic, not a distributed transaction.
5. [conversation_profile.py](../services/api/lab/conversation_profile.py), [learner_context.py](../services/api/lab/learner_context.py) and [chat_prompt.py](../services/api/lab/chat_prompt.py): the latest compact saved state is loaded each turn. Full literal CV text is included only when explicitly enabled and stays protected, alongside policy and the full question. Existing history/evidence may be trimmed; required context may not.
6. [prerequisite_import.py](../services/api/lab/prerequisite_import.py) and [web/prerequisite_imports.py](../services/api/lab/web/prerequisite_imports.py): an explicit immutable historical snapshot goes to the captured existing main conversation. Later replies still load current answers independently. This action does not call a model or send a question automatically.
7. Frontend [profile API](../apps/web/src/api/profile.ts), [useProficiency](../apps/web/src/hooks/useProficiency.ts), [proficiency domain](../apps/web/src/domain/proficiency.ts), and [MyProficiencyPanel](../apps/web/src/components/MyProficiencyPanel.tsx): wire validation → effects → pure view transformations → rendering. App is the composition root; shared activity guards prevent overlapping writes/chat.

8. [usePrerequisites](../apps/web/src/hooks/usePrerequisites.ts) loads saved section results and orchestrates explicit generation. [useFocusedAssessment](../apps/web/src/hooks/useFocusedAssessment.ts) independently reloads the historical assessment saved in a conversation; its historical-only API query validates saved history without reading current CV artifacts or map eligibility. [RequirementAnswers](../apps/web/src/components/RequirementAnswers.tsx) shares pending/four-choice/notes/save behavior between both views and refuses missing or ambiguous saved associations. [usePrerequisiteImport](../apps/web/src/hooks/usePrerequisiteImport.ts) captures an existing conversation and explicitly adds the immutable snapshot, separately from an editable unsent follow-up. Final browser proof remains tracked in the implementation notes.

Using the same model does not mean sharing request tokens: the gateway sends a new explicit messages array for each request. The saved chat history is stored by the app and included only by chat orchestration. Prerequisite planning supplies a different fresh array. The shared inference lock serializes requests for local memory bounds; it does not merge their contexts. Temperature0 applies to structured requests to improve repeatability, and ordinary chat keeps its existing sampling. No separate model, autonomous agent, automatic research or hidden course-generation loop is introduced.

Run relevant tests from `services/api` with `../../.venv/bin/python -m pytest tests/test_prerequisites.py tests/test_prerequisite_store.py tests/test_learner_profile.py tests/test_conversation_learner_context.py -q`. Browser verification must use the isolated launcher/fixture policy, never personal topics/CVs. Follow [the full API contract](API.md#shared-cv-my-proficiency-and-prerequisites) for persistence, failure ordering and current limits.
