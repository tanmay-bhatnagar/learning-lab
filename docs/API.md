# Initial build API contract
FastAPI localhost:8765; Vite localhost:5173 proxies /api. JSON errors use detail. Files and conversations scoped by validated topic ID. Models have no filesystem tools. Flat JSON persistence lives inside each topic; settings are separate.
GET /api/health
GET /api/topics -> {topics:[{id,name}]}
POST /api/topics {name} -> {id,name}
GET /api/topics/{topic} -> {id,name,learning_goal?}; older topic records may omit the optional goal.
PUT /api/topics/{topic}/learning-goal {learning_goal:string<=2000} -> saved goal. Empty text clears it. Chat includes a nonempty value as explicitly user-authored topic context.
GET /api/topics/{topic}/files -> {files:[{id,name,status,parser,markdown_name?,docling_name?,chunks_name?,parse_name?,index_status?,index_mode?,page_count?,asset_count?,warnings?,extraction_diagnostics?,error?,interrupted?}]}. Docling diagnostics use confirmed_failure, suspected_limitation, or unassessed; no reported issues leaves fidelity unassessed. Legacy and older records are displayed as unassessed. A `processing` record that no running upload owns is returned as `status:error` with `interrupted:true`; the change is saved when the topic is idle, and the original PDF and any partial artifacts are kept.
POST /api/topics/{topic}/files multipart file and parser (docling|markitdown|anydoc) -> file record (conversion is synchronous in a worker thread). Docling is the default. It persists native JSON, Markdown, chunk JSONL, page renders, figure crops, a version 2 parse manifest with extraction diagnostics, and a topic-scoped SQLite retrieval index. Older manifests remain readable. `page_count` counts pages in the parsed document whether or not page renders exist. MarkItDown and AnyDoc remain unindexed fallback converters.
GET /api/topics/{topic}/files/{file}/markdown -> {markdown:string}
GET /api/topics/{topic}/files/{file}/original -> PDF; browser fragment `#page=N` opens a cited page where the PDF viewer supports it.
GET /api/topics/{topic}/files/{file}/parsed -> DoclingDocument JSON
GET /api/topics/{topic}/files/{file}/chunks -> {chunks:[...]}
GET /api/topics/{topic}/files/{file}/assets/{asset_id} -> PNG
POST /api/topics/{topic}/retrieval/trace {query,file_ids?:[],top_k?:6} -> {query,hits:[...],mode:keyword|hybrid|fallback|none,warning?}. Every hit includes filename, headings, page/bounding-box provenance, linked visual names, and keyword/embedding/fusion ranks and scores. Fallback mode returns at most two opening chunks when a selected file has no lexical or semantic match.
GET /api/topics/{topic}/conversations -> {conversations:[{id,title}]}. The `default` conversation maps to legacy `session.json`; catalog creation and recovery do not rewrite that file or saved conversation sessions. Valid saved conversation files absent from a missing or existing catalog reappear with an explicit `Recovered chat <id prefix>` title that can be renamed. Invalid catalog IDs, a missing or duplicate default, duplicate IDs, and missing referenced conversation sessions return CorruptData (HTTP 500) without rewriting the catalog.
POST /api/topics/{topic}/conversations {title} -> {id,title}
PATCH /api/topics/{topic}/conversations/{id} {title} -> {id,title}
GET /api/topics/{topic}/conversations/{id}/messages -> Session (same shape as legacy messages).
POST /api/topics/{topic}/conversations/{id}/chat -> same request and NDJSON stream semantics as legacy chat. Conversation IDs are topic-scoped; an ID from another topic returns 404. New sessions are flat `conversation_<id>.json` files.
Legacy `/api/topics/{topic}/messages` and `/api/topics/{topic}/chat` address `default`.
GET /api/topics/{topic}/query-traces?conversation_id=default&limit=100 -> {traces:[...]}. Omit `conversation_id` to list all requests within that topic, newest first; a supplied conversation must belong to the requested topic. `limit` is 1–1,000 (default 100). Invalid limits return 400; malformed integer parameters return 422. No cross-topic list exists. Trace reads are read-only and return an empty list when that topic has no trace database.
Each trace carries `schema_version:1`, `id`, `topic_id`, `conversation_id`, UTC `started_at`/`finished_at`, and `status:started|completed|rejected|error|cancelled`. Metadata includes `query_chars`, `requested_model`, `requested_think`, `context_limit`, reported `actual_model` when available, `embedding_model`, `retrieval_top_k`, `selected_file_ids`, `retrieved_chunks`/`retained_chunks` (chunk/file identity, page, rank and score), `retrieval_mode`, a categorized `retrieval_warning`, `prompt_budget`, `context_used`, optional `final_context` with the existing usage/limit/estimated/trimming flags, `preflight_ms`, `retrieval_ms`, `generation_ms`, `first_output_ms`, `total_ms`, `output_chars`, `thinking_chars`, `stage`, sanitized `error`, optional `cleanup_error`, `user_saved`/`assistant_saved`, and nullable zero-based user/assistant message indices. Stage data unavailable before rejection is null; characters and stream fragments are not token counts.
Trace records live in flat topic-local `query_traces.sqlite`, separately from saved conversation JSON and `retrieval.sqlite`. Valid-body chat requests for safely resolved topics are traced before acquiring the topic lock; malformed bodies, missing/unsafe topics and middleware rejections are outside that boundary. Completion requires model completion and saved answer; cleanup failures can be reported separately without relabeling that completed answer. Abrupt process termination can leave a visibly unfinished `started` row. Requests never duplicate query/prompt/answer/thinking text, citation excerpts or images in traces. See [query_traces.md](query_traces.md) for timing semantics, persistence compatibility and failure handling. Retrieval-quality evaluation remains separate.
Browser persistence: selected file IDs are saved per topic/conversation in browser `localStorage`, validated against the current file list, and are not synchronized between browsers. A full page reload opens `default`; other conversations remain available in the picker with their server-saved histories. The learning goal and uploaded PDFs belong to the topic. These choices satisfy the current saved-conversation increment; cross-browser selection and restoring the last active conversation are not implemented.
Cancellation: switching conversations waits for browser stream cleanup; message reads wait for the topic lock so server finalization is visible before history loads. Switching topics or unmounting aborts the browser upload batch and prevents later files in that batch from starting. Conversion already accepted by the server may finish and persist in the original topic; return to that topic and refresh files to inspect its result. Browser abort does not promise server-side rollback.
GET /api/topics/{topic}/messages -> {messages:[{role,content,thinking?,model?,incomplete?,retrieval?}], context?:object}. Assistant messages may include `retrieval:{mode:keyword|hybrid|fallback|none,warning?,citations:[{chunk_id,file_id,file_name,headings,pages,bboxes,assets,trace,text?,chunk_index?}]}` persisted per answer so earlier sources survive later turns.
POST /api/topics/{topic}/chat {message, file_ids:[], model, think?:bool|string, context_limit:32768} -> NDJSON events {type:thinking|token,text}, {type:done,context:{used,limit,estimated,truncated_messages},retrieval:{mode,warning?,citations:[]}}, {type:error,message}. The done event's retrieval object is also saved on the assistant message. A prompt that cannot fit the minimum required context returns HTTP 422 with a detail message and is not appended to history. Higher-ranked evidence is retained first when context is tight; evidence messages are atomic so trimming never sends a partial passage without its location wrapper. Citations cover only evidence messages retained by request-local context trimming. A selected ready indexed file whose topic retrieval database is missing returns HTTP 409 with recovery guidance; the API does not silently continue without its evidence. Indexed Docling files use bounded retrieval instead of whole-document injection. Selected legacy files retain whole-Markdown attachment behavior. Prompt history sent to the model includes only role/content/thinking — never citation metadata.
GET /api/models -> {models:[{id,name,size_bytes,quantization,parameter_size,vision:boolean,thinking:{type:none|toggle|always|levels,levels?:[]}}], error?:string}
GET /api/settings -> {model:string,context_limit:number,parser:string,embedding_model:string,retrieval_top_k:number}
PUT /api/settings same object -> settings; browser can persist think per model.

Model module contract (services/api/lab/models.py): async list_models()->dict; async embed_texts(texts:list[str], model:str, *, generation_lock)->list[list[float]], raising `EmbeddingUnavailable` (lab.contracts) when the model is not installed or Ollama is unreachable and ValueError for rejected input or malformed vectors. Unavailable embeddings degrade uploads to a keyword index and searches to keyword retrieval with a warning; rejected document embeddings fail indexing, while a rejected query embedding falls back to keywords; async stream_chat(messages:list[dict], model:str, think:bool|str|None, context_limit:int) yields above NDJSON dict events. Context truncation internal; never drop system messages, preserve recent user text; full durable history unaffected. Retrieved evidence and attachments are separate, trimmable user-context messages and are never treated as trusted system instructions. Vision-capable models may receive retrieved figure PNGs as Ollama `images`; base64 is never persisted in session history. Modules import package lab. Response-budget cutoffs emit an error and preserve partial output as incomplete.

Context limits: 1,024–32,768, default 32,768. Full topic history is persisted separately from the trimmed request. Embedding chunk boundaries use the selected local tokenizer with embedding special tokens when available and an approximate byte-based estimate otherwise; fallback estimates cannot guarantee model token limits. A chunk that cannot fit with its headings fails indexing with an actionable error. Files must have a PDF header and fit the 25 MiB upload limit. Localhost-only origin/host checks are enforced. Settings can be isolated with LEARNING_LAB_STATE_ROOT; topics with LEARNING_LAB_ROOT.

Model records also include `display_name` and app-capped `max_context_length`. Completed chat events and saved assistant messages include `model` so the UI can attribute each answer. New settings default to Docling parsing; MarkItDown and AnyDoc remain available as unindexed fallback converters. Unsupported graded thinking requests for toggle-only models are rejected explicitly.

## Runtime learning policy

Both chat endpoints read the configured UTF-8 runtime policy before retrieval, model calls, or saving the user turn. Missing, unreadable, blank, or invalid UTF-8 policy returns HTTP 500 with an actionable `detail`; the request records a preflight error trace and saves no conversation turn. The full policy is protected during context budgeting; an unfit policy returns HTTP 422 rather than being omitted or shortened. Non-chat APIs remain available. Configuration and evidence: [runtime policy loading](runtime_policy.md).

## On-demand document outlines

`GET /api/topics/{topic}/files/{file_id}/map` returns `{status:not_built|ready|stale,map:null|record}`. Reading does not build a map or invoke inference. `POST` at the same URL explicitly builds/rebuilds from the original PDF and saved native Docling artifact; identical revisions preserve saved state. Both files must belong to the topic and extraction must be ready. Embedding/index readiness is not required. Markdown-only artifacts cannot provide native sections.

Map schema v1 includes file/revision/source identity, builder version, outline mode (`headings|pages`), recursive sections, ordered source units, coverage, warnings and prior revision history. Revision binds actual PDF bytes and exact structured-artifact bytes. Missing stored map means not built; corrupt/unsupported/inconsistent file identity, source ownership or coverage fails visibly. A valid map whose actual source changed is stale. Rebuild preserves the prior snapshot and does not reassign summaries by heading title.

`GET .../map/sections/{section_id}` returns `{status,section,source_units}`. Section `text` is direct introductory/owned extracted text; `source_unit_ids` and returned source units cover descendants once in canonical document order. Pages include merged-caption provenance. The outline nests only from saved heading levels; missing headings use page-oriented item ownership and absent provenance uses Unlocated. Invalid existing-page references and ambiguous shared captions fail visibly. Coverage accounts for extracted material and explicit exclusions, not certified fidelity against PDF pixels. `latest_attempt` and `last_summary` are initially null; summary generation is a separate operation.
