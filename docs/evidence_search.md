# Answer-or-search — implementation study path

The backend and browser implementation are complete. The feature is off by default: select an indexed document, then enable **Allow extra search** for one message. Live progress is separate from model thinking; each saved answer records whether the extra search added evidence. The [19 October continuation](reports/evidence-retrieval/2026_10_19_evidence_retrieval_implementation.md) records checkpoint status and verification limits. Earlier [research](reports/evidence-retrieval/2026_10_15_evidence_retrieval_research.md), [design](reports/evidence-retrieval/2026_10_15_evidence_retrieval_design.md) and [accepted discussion](reports/evidence-retrieval/2026_10_15_evidence_retrieval_discussion.md) remain separate historical reports.

The experiment gives the selected local chat model one bounded choice after ordinary retrieval: answer from the supplied context, or request one more search within selected indexed documents. A direct answer needs one generation. A search needs at most two generations and one additional lookup. The app owns the selected document IDs and executes lookup; the model supplies only a query. There is no second routing model, side conversation or repeated search loop. Since the 20 October pivot the sequence runs as a LangGraph graph; the event contract and saved records are unchanged.

Read these modules in order:

1. [evidence_request.py](../services/api/lab/evidence_request.py) owns pure action validation and selected-source merging. Its schema helps the provider produce the four requested fields; the completed-output parser separately enforces branch exclusivity, byte limits, labels and inline markers. The schema alone is not enforcement. Labels bind to full source hashes, rather than a short citation excerpt.
2. [evidence_prompt.py](../services/api/lab/evidence_prompt.py) adds labels/instructions to the existing [chat_prompt.py](../services/api/lab/chat_prompt.py) budget path. It returns the exact retained source manifest and hashes of images actually attached. Final source ordering alternates novel follow-up passages and initial passages, starting with a novel passage. This gives the additional lookup a chance to survive trimming without comparing unrelated query scores. It is a deterministic allocation rule, not a measured optimal ranking.
3. [evidence_snapshot.py](../services/api/lab/evidence_snapshot.py) owns boundary reads and immutable prompt-relevant identities. Raw prompt inputs are returned separately from the digest record. Revalidation compares relevant policy, goal, proficiency, opted-in CV, selected files and accumulated supplied sources/images. Unrelated profile or index updates should not invalidate a turn. Checks occur before effects; they do not freeze all stores atomically.
4. [workflows/chat_evidence.py](../services/api/lab/workflows/chat_evidence.py) owns the bounded sequence of model and lookup effects as a LangGraph execution graph (`evidence_init → decision → direct_answer | invalid_prepare | lookup → merge_final_plan → stream_final_answer → prepare_publication`), with pure decision, scope and merge helpers in [evidence_result.py](../services/api/lab/evidence_result.py). It buffers the first response until provider completion, validates the action, closes that provider iterator before embedding/search, and uses an ordinary streamed answer for the second generation. [workflows/chat.py](../services/api/lab/workflows/chat.py) admits the turn (captured prompt assembly and the user-message save); [workflows/chat_publication.py](../services/api/lab/workflows/chat_publication.py) prepares and commits the assistant record and compact trace metadata; [workflows/chat_stream.py](../services/api/lab/workflows/chat_stream.py) owns the run handle, NDJSON events and teardown; [the HTTP adapter](../services/api/lab/web/chat.py) acquires the topic lease and returns the response. The [workflow study path](workflows.md) explains the runtime. [FinalizedStreamingResponse](../services/api/lab/web/middleware.py) observes disconnect even while planning output is buffered. Follow the dated note for browser/runtime evidence and its limits.

5. On the browser side, [api/types.ts](../apps/web/src/api/types.ts) validates the additive wire contract and older saved histories. [domain/evidenceSearch.ts](../apps/web/src/domain/evidenceSearch.ts) owns pure progress folding and saved outcome counts. [useChat.ts](../apps/web/src/hooks/useChat.ts) owns per-conversation opt-in, reset on accepted requests, cancellation and transport cleanup. [EvidenceSearchDisclosure.tsx](../apps/web/src/components/EvidenceSearchDisclosure.tsx) renders durable outcomes independently of citation availability; [citations.tsx](../apps/web/src/citations.tsx) adds evidence labels alongside readable filenames and page links.

Each gateway call receives an explicit messages array. The same local model weights can serve both requests without sharing an implicit token history. The app rebuilds each request with complete protected policy, question, relevant proficiency and optional complete literal extracted CV text, plus bounded history and retained evidence. The shared inference lock serializes generation and embedding for memory control; it does not combine contexts. Closing the first provider before lookup avoids holding that lock while embedding waits for it.

The first answer is buffered because partial JSON is not a valid completed answer. A completed but invalid action permits one ordinary fallback answer with a visible fixed warning. A failed, oversized or unterminated provider stream fails visibly without another generation. This distinction preserves the two-call ceiling while avoiding a hidden retry after provider failure.

Source accounting distinguishes initial available, initial retained, returned, novel returned and retained novel passages. A newly returned passage can be trimmed; a previously trimmed initial passage can be returned again without being novel. Declared labels are separate from all supplied citations. None of these counts proves that a claim is supported, that evidence is complete, or that the model selected a useful query. Those require inspecting actual answers and the underlying documents.

Freshness also covers initial sources omitted by the final prompt: the model already inspected them during its decision. Actual final citations and context usage still describe the final call. CV-off checks do not read CV registry/artifacts. With CV inclusion on, complete extracted text remains protected in both requests; it is not searched by this operation. Fixed outcome warnings keep arbitrary provider/search messages, generated queries, CV wording and planner thinking out of compact diagnostics.

Use synthetic fixtures and isolated roots for verification. The dated notes distinguish unit contracts, independent review, actual model probes and full application proof; passing one category does not establish the others.
